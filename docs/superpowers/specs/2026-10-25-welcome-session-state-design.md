# 欢迎页账号状态修复

用户已于 2026-10-25 确认按最小改动方案实施。

## 问题与实测边界

正式 .3→.4 经 GitHub 下载、校验、原目录覆盖和自动重启成功，数据及新备份通过独立核对。升级后进入个人空间仍为原试点账号，无需重新登录，记住我实际保留。欢迎页的固定“登录”按钮误导了验收，不能据此判断 Cookie 或会话丢失。

## 已确认行为

- 沿用路由现有的服务端账号恢复，不新增凭据存储或认证接口。
- 初次恢复及用户主动重试期间显示禁用的“正在确认账号…”。
- 已确认登录时显示“我的空间 · 昵称”，无昵称时使用用户名，点击进入个人空间。
- 服务端明确未登录时显示“登录”，沿用现有登录导航。
- 确认请求网络失败时显示“重试确认账号”；点击仅重试账号确认，不提交登录，不将网络失败当注销。
- “进入本地空间”和 Enter 键入口始终可用，不自动跳过欢迎页，不改开屏动画和现有路由权限。

## 实施与验收

1. 在 WelcomePage 使用现有 auth store 的 loaded、user 和 sessionCheckError，添加局部重试中状态，防止重复请求。
2. 用可控的真实浏览器请求夹具覆盖恢复中、已登录、未登录和失败重试；断言无登录提交、本地入口不阻塞、键盘及小屏无溢出。
3. 运行相关欢迎页、开屏、本地导航、登录及发布日志测试、类型与构建检查。新源码的完整 CI 与真实打包升级须独立复验，不能沿用旧二进制的结论。
4. 已发布 .4 不覆盖资产或标签，当前保持暂停和唯一成员；后续使用新版本发布，四项同步规则不变。

## 自检

改动仅作用于欢迎页账号入口。会话有效性仍由后端判断，不读取 Cookie 值、不改系统信任、权限和数据结构；未约定或未执行的生产放量不记为完成。
