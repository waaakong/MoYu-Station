# 下一版本安全初审与整改范围

日期：2026-10-26；源码基线 main c6af9c4。状态：静态初审，不是完整渗透测试或安全认证。未对生产执行攻击、并发负载、权限变更或数据库写入。

## 已观察问题

### 1. 音乐元数据解析缺少可终止的进程边界（优先）

`desktop/src/audio/library/metadata.ts` 中 `readAudioMetadata` 直接调用 music-metadata 的 parseFile，再与定时器做 Promise.race。`scanner.ts` 接受 m4a 等本地文件，且该模块被主进程构建打包。定时器不能中断同步死循环，也不取消尚未结束的解析，不能作为恶意媒体解析的强制资源边界。

本机 npm audit 报告 music-metadata <11.16.0 的解析拒绝服务告警，包括 GHSA-f94x-6692-553q 和 GHSA-5gfj-9q3v-qfp3。公告范围不等于已复现本制品；其中 MP4 公告标题注明未发布分支回归，尤其不能仅凭扫描范围断言当前版本可触发。

建议升级经过核对的修复版本，并把解析放入可终止的受限子进程，限制输入体积、解析时间、并发及返回数据。超时真正终止工作进程，主客户端继续使用。受害者需导入／扫描恶意本地文件；目前没有远程无交互触发证据。

### 2. 代理来源地址信任链不一致（优先）

`deploy/nginx/proxy-headers.conf` 使用 `$proxy_add_x_forwarded_for` 追加客户端已有的头；`AuthRateLimiter.clientAddress` 在回环代理请求时取 X-Forwarded-For 最左项。该组合可能将外部伪造的首项当作用户地址，从而削弱地址维度限流及日志可靠性。用户名维度限流仍存在，因此不是完全绕过登录限流。

建议单层公网入口覆盖来源头为真实连接地址；多级代理仅信任明确代理列表并从可信边界解析。应用端不能一概信任客户端头。先只读核对实际生产代理拓扑及有效配置，再在隔离实例复现与验收；尚未确认生产当前采用该配置或已经被利用。

### 3. 外部链接校验可收窄（加固）

`desktop/src/main/security/navigation.ts` 只检查 HTTPS 与域名白名单，没有显式拒绝 userinfo、非标准端口或按用途约束路径。现有逻辑不允许任意主机，也没有证据证明能执行任意程序；这是缩小钓鱼／意外跳转面的加固项。

建议拒绝带凭据 URL、非预期端口和异常长度；下载页／仓库入口采用固定用途路径，不能为修复酷狗而放宽此通用入口。测试保留合法外部链接。

## 依赖初筛

对当前本地依赖执行 `npm audit --omit=dev --json`，报告 8 个受影响包（7 high、1 moderate），这是受影响包计数，不是 8 条可利用路径。涉及 axios、follow-redirects、music-metadata、zod、vue、@vue/server-renderer、source-map-js、vite。原始输出留在私有验收目录，未公开日志。

axios 1.18.0 在前端使用，自定义桌面 adapter 与浏览器 adapter 的可达性不同，不能将 Node HTTP/2 告警直接套到网页。Zod 4.6.2 被打包到桌面验证边界，需结合上游体积限制检查超大集合内存消耗。Vite 是开发／构建工具，存在审计结果不意味着生产运行了公开 Vite 服务。升级应逐组验证，禁止盲目 audit fix 或用删除断言掩盖回归。

后端 pom 的 Spring Boot 基线为 2.7.18；本次尚未完成有效 Maven 依赖树／CVE 扫描及支持状态核查，不能宣称后端依赖安全。该项需独立 SBOM、公告匹配、可达性分析与兼容迁移评估。

## 已存在的保护

- 主窗口、歌词窗具有隔离／沙盒及禁用 Node 配置，IPC guard 验证 sender 和主 frame，并有每通道速率／并发限制。
- 平台传输使用固定接口、HTTPS、DNS 公网地址检查、响应大小／时间限制，不接受调用方任意目标。
- 凭据保管使用平台加密，不支持明文回退；Windows 实际 ACL 尚需核对，不能仅凭 mode 0600 断言文件隔离。
- 后端写请求有来源与 CSRF 校验，管理员高风险操作有本人复验；登录具有账号／地址双维度限流和有界本地降级。
- SocketSessionGuard 在收发检查实时会话与账号撤销版本。
- 图片处理已有子进程、共享单并发许可、超时终止及环境变量裁剪；这不等于操作系统权限沙盒，也不是总驻留内存限制。
- 更新已具备签名清单、身份／长度／哈希、资格复核和安装前备份；未签名安装包仍不是受信任 Authenticode 制品。

这些是代码中存在的防护，不替代生产有效配置及绕过测试。

## 本版进一步核查与门禁

1. IPC：逐入口核对输入大小、资源路径、所有者、聚合并发和新轮盘权限；拒绝非预期窗口与跨 frame。
2. 认证：封禁／改密／退出／切号时 HTTP、WebSocket、媒体和更新授权一致失效；管理员复验和乐观版本不因中文文案改变。
3. 上传：路径穿越、伪造 MIME、超像素／恶意 GIF、配额、图片私有引用和跨账号访问；不能只按扩展名信任文件。
4. 网络：媒体 URL、DNS 重绑定、重定向、私网／IPv6、凭据跨域隔离及 SSRF；不会为播放兼容性允许任意 CDN。
5. 数据：草稿／曲库／游戏存档输入校验、权限、备份一致性及损坏恢复；不将真实数据导入测试。
6. 发布：原生输入辅助进程来源、固定路径、哈希、有限协议；依赖锁定、许可证及敏感信息检查。

问题先以隔离单测／本地夹具证实，再按实际风险整改并回归。没有完成的生产配置、后端依赖、渗透与真实平台验证必须保留状态，不写成“安全漏洞全部修复”。
