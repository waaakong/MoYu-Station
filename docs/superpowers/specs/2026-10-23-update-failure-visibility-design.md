# 更新失败跨页提示设计

日期：2026-10-23。范围：既有一键更新流程的错误可见性修复，不新增更新授权。

## 已确认目标

用户已确认：复用现有全局更新浮层，失败后跨页保留具体原因与错误码，提供“重新检查”和“关闭”；关闭提示不恢复安装授权。修复及剩余门禁通过后，按既有发布计划仅对 WaaaKong 开展生产试点，不直接扩大受众。

## 问题与选择

当前 `UpdateLifecycleHost.vue` 只在 `updateIntent` 为真时显示。主进程正确地在失败后撤销安装意图，因而错误提示也随之消失。个人页仍保留错误状态，但在其他页面操作的用户看不到原因。

采用现有浮层承载进度和终止错误，避免新增独立通知系统。替代的独立常驻通知条可实现相同可见性，但需要额外同步与去重，不采用。不得通过保留或重新设置安装意图来保持浮层显示。

## 状态与交互

- 安装意图、验签、下载、保存、备份与安装仍由主进程管理，IPC 白名单及权限判断不变。
- 前端更新 store 独立保存本次用户更新操作产生的错误通知。错误通知不是安装意图，也不写入磁盘，不跨客户端重启恢复。
- 本次用户操作失败时，即便主进程已撤销意图，全局浮层仍显示面向用户的具体原因及已有错误码；不展示原始异常、路径、凭据或会话信息。
- 浮层不阻断页面操作、不抢焦点。路由切换、同一错误的重复状态推送及后台检查不得清除或反复弹出同一通知；无关后台检查失败不产生新的常驻弹层。
- “关闭”只隐藏本次错误通知，不修改主进程状态、不重试、不开始下载或安装；用户仍可在客户端版本页查看当前错误。
- 可重试错误提供“重新检查”，仅调用既有检查动作。重新检查成功不等于同意安装，必须由用户再次点击更新；不可重试错误不提供无效重试按钮。
- 用户主动重试后再次失败，需要显示本次新错误；不能因用户关闭过上次相同错误而永久静默。
- 退出登录、切换账号及 store 销毁清除旧通知，不将上一账号的操作通知带入新会话。
- 下载、忙碌等待、倒计时、取消和安装期间现有行为保持不变。失败提示上不显示“取消本次更新”，因为失败后的安装意图已撤销。

## 改动边界

优先仅调整 `frontend/src/stores/updates.ts`、`frontend/src/components/window/UpdateLifecycleHost.vue` 及对应测试。版本页复用现有原因和错误码，不引入新的错误分类。无数据库迁移，不修改证书信任、来源白名单、自动安装授权、系统代理或音乐平台权限。原脏工作区不参与构建。

## 验收

1. 真实更新操作失败后，社区、声音、专注等非版本页均能看到具体原因和错误码，切页不消失；错误发生时安装意图为假，当前版本仍可使用。
2. 关闭、重复推送、重新检查、同码再次失败、退出登录及切号分别验证；不出现偷偷安装、旧账号通知残留或焦点抢占。
3. 验证草稿、专注、播放等待及倒计时取消没有回归；检查键盘、减少动态和 1440×900、1280×720、1080×640、390×844 布局，失败项单列。
4. 单元、类型、构建和边界检查通过；新源码 GitHub Linux 浏览器功能 CI 连续两次零重试通过。不新增跳过、不删断言、不放宽截图容差。
5. 新固定制品上执行真实失败可见性及恢复；原物理机升级通过记录按原版本保留，不冒充新版本已安装验收。签名／哈希、权限、撤回、授权失效、断网等剩余故障矩阵逐项以实际证据收口。

## 生产边界

仍使用清单签名模式，Windows 安装包未获受信任 Authenticode 签名，不修改系统信任库或绕过 UAC。门禁未完成前不投放新正式制品。

门禁通过后，固定新版本、源码和校验值；备份并安装必要的生产入口引导版，再仅向 WaaaKong 推送后续版本，验证实际下载、覆盖安装、自动重启及真实数据保留。如正式客户端运行，先由用户正常退出，不强制结束。任何安装或数据异常立即暂停。

每次正式发布同步安装包、下载页、更新日志及 GitHub 源码／发布记录，四项齐备才报告完整发布；不上传私钥、会话、用户库、测试截图和私人日志。回退仅处理兼容应用及配置，不用旧备份覆盖新增用户记录。
