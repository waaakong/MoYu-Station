# 更新失败可见性实施与验收计划

已批准设计：`../specs/2026-10-23-update-failure-visibility-design.md`。

1. 在更新 store 中分离本次用户操作、错误通知和主进程安装意图；通知只保存在内存，支持关闭、主动重查、新失败及账号边界清理。
2. 全局现有浮层增加终止错误分支，展示原因/错误码、受 canRetry 约束的重新检查及关闭。关闭只影响通知；主进程、IPC 和签名策略不变。
3. 单元覆盖失败撤销意图、重复/迟到状态、关闭、新尝试同码失败、后台检查静默、重查不安装、退出/切号/销毁；保持既有保存/草稿测试。
4. Playwright 覆盖跨页提示、键盘关闭/重查、不可重试、无抢焦点及四个既定视口，现有倒计时/保存用例继续运行，零重试。
5. 类型、单元、边界、敏感信息、构建检查及截图核对通过后，定向提交源码和脱敏记录；新冻结源码 GitHub CI 连续两次零重试通过。
6. 从该源码构建新版本，补齐真实错误可见性、剩余故障和升级门禁；原旧制品通过记录不覆盖。必要 GUI 操作由测试机 UU 桌面执行，SSH 不代替可见桌面启动。
7. 门禁通过后，按原发布规则备份、生产入口引导、仅 WaaaKong 推送试点、下载页/日志/GitHub 四项同步。任一数据或安装异常立即暂停，不扩大受众。

writing-plans 技能当前不可用，使用本显式计划，不跳过任何原验收门禁。
