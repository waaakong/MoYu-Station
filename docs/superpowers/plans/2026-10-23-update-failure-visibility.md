# 更新失败可见性实施与验收计划

已批准设计：`../specs/2026-10-23-update-failure-visibility-design.md`。

1. 在更新 store 中分离本次用户操作、错误通知和主进程安装意图；通知只保存在内存，支持关闭、主动重查、新失败及账号边界清理。
2. 全局现有浮层增加终止错误分支，展示原因/错误码、受 canRetry 约束的重新检查及关闭。关闭只影响通知；主进程、IPC 和签名策略不变。
3. 单元覆盖失败撤销意图、重复/迟到状态、关闭、新尝试同码失败、后台检查静默、重查不安装、退出/切号/销毁；保持既有保存/草稿测试。
4. Playwright 覆盖跨页提示、键盘关闭/重查、不可重试、无抢焦点及四个既定视口，现有倒计时/保存用例继续运行，零重试。
5. 类型、单元、边界、敏感信息、构建检查及截图核对通过后，定向提交源码和脱敏记录；新冻结源码 GitHub CI 连续两次零重试通过。
6. 从该源码构建新版本，补齐真实错误可见性、剩余故障和升级门禁；原旧制品通过记录不覆盖。必要 GUI 操作由测试机 UU 桌面执行，SSH 不代替可见桌面启动。
7. 门禁通过后，按原发布规则备份、生产入口引导、仅 WaaaKong 推送试点、下载页/日志/GitHub 四项同步。任一数据或安装异常立即暂停，不扩大受众。

writing-plans 技能当前不可用，使用本显式计划，不跳过任何原验收门禁。

## 真实下载复验后的定向修正

- 前一冻结源码的两轮完整 CI 通过，但新物理复验在下载阶段失败，不能据此宣称升级门禁通过。旧证据和候选制品保留，不覆盖或重发。
- 单独复现：Chromium `ERR_CONTENT_LENGTH_MISMATCH` 被宽泛的 `MISMATCH` 匹配误报为通道错误。新增精确传输代码识别及可重试提示，真实签名、清单、通道与哈希拒绝逻辑不放宽。尚无原始异常证据证明这就是该次物理下载失败的唯一原因。
- 回归同时核对结构化传输代码、签名优先级、哈希优先级、授权撤销与不自动安装。本修正涉及主进程，需重新冻结源码、连续两轮 CI 和新物理制品验收，不能沿用旧二进制通过记录。
- 新生产入口候选使用不可变版本 `.20261023.3/.4`，仅准备、不发布；既有 `.1/.2` 候选保留。生产推送保持关闭，直至约定门禁与本人试点就绪。

## 真实磁盘错误提示复验后的定向修正

- 无原生断点的物理 Windows 10 复验确认：真实专用小容量卷耗尽后返回 `UPDATE_DISK_INSUFFICIENT`、撤销意图并保持原版本，但全局面板的中文原因仍落入笼统的检查／下载失败提示。因此该轮没有通过具体原因、跨页恢复及最终升级门禁。
- 仅补充现有错误码的主进程安全文案映射，说明磁盘空间不足、已阻止安装、释放备份及更新文件所在磁盘空间后重新检查；不暴露原始异常或路径，不改错误分类、授权、验签和安装逻辑。
- 下载空间不足与备份空间不足各增加具体文案断言；备份失败继续验证撤销意图、不可安装、后续计时及正常退出均不启动安装器。两项新增断言已在修复前实际失败，不能通过删除或放宽真实验收断言来消除问题。
- 该修正需要新的冻结提交、两轮零重试 CI、新不可变实验与正式候选及真实复验；旧制品和旧失败保留，不宣称旧异常升级原因已经定位。
